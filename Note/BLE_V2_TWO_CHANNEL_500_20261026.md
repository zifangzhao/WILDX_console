# V2 BLE preview: two channels at 500 samples/s

The requested preview target is one or two selected P1/P2 channels at **500 samples/s per channel**. Native P1/P2/P3 SD logging and IMU/control priority remain the acceptance criteria. Four channels at 250 Hz is superseded. P3 preview is still unavailable; its separate SPI lane is not silently substituted.

The firmware filters selected native ADC samples before downsampling. A four-stage integer CIC plus Q23 FIR suppresses aliases into 0–200 Hz; the independent model gives at least 64 dB worst alias rejection and at most 1.021 dB attenuation at 200 Hz across the four supported native rates. This supports the approximately 80–200 Hz ripple band. The 250 Hz Nyquist limit does not imply a flat usable response up to 250 Hz, and no claim is made for higher-frequency ripples. Q3 output retains one-eighth nominal ADC-count resolution. Native recorded samples are not filtered by this preview path.

Each 80 ms packet holds 40 original time rows for both traces, source-clock center timestamps, channel offsets, sequence and CRC. The filter delay is already removed in firmware; the GUI never removes it again. Cumulative feedback acknowledges every two packets and requests replay after a missing/corrupt packet. The firmware retains 32 packets (2.56 seconds); the GUI uses a 320 ms display lead. Short losses recover original values and timestamps without interpolation. Longer outages or recording pressure can end preview explicitly; finite buffering is not an unlimited RF guarantee and never backpressures logging.

The capability query selects this extension only on supported firmware. An explicit unsupported reply selects the existing single-channel preview on older V2 firmware. V1's existing compact preview and recording path remain in place. Channel selection keeps Preview checked; window, gain and display HPF change only the view. New filtered plots show nominal ADC counts, not factory-corrected or microvolt values. An uncertain GATT write is not replayed or followed by a repair command.

Software checks: `test_ble_preview_multi.ps1` passes 303 codec/replay assertions; `test_ble_preview_display.ps1` passes 219 new actual-source GUI checks and 6,107 legacy checks with only the radio doubled. These cover loss/reordering/CRC/replay, 500 Hz pacing, one shared probe-framing snapshot, IMU/control priority, selection changes, V1 compact admission and old-firmware fallback. Truncated binary preview cannot indefinitely hold a later CRC-valid short recording receipt.
