# USB download byte-rate meter — WILD-X 1.0.0.150

The V1/V2 USB download MB/s display now uses accepted payload bytes divided by elapsed time for the current recording. It no longer derives speed from whole-percentage progress. A large file's percentage can remain unchanged for seconds, making the old estimate decline and then jump despite steady USB throughput. This matches the reported 30–43 MB/s pattern and the preceding 149 measurements.

One atomic 64-bit counter increments at the shared reply-validation point after header, sequence, address and payload CRC checks. Normal and burst reads share that point. Rejected replies, unvalidated speculative replies and reads served from an existing cache do not add bytes. A new recording takes a counter baseline, excluding prior catalog/recording reads. The counter is safe across background-prefetch threads and above 4 GiB. The displayed rate is the recording's average validated USB payload throughput; actual stalls remain reflected in that average. The initial fraction of a second displays Measuring speed instead of an unstable number.

The percentage bar, approximate processed GiB and phase/queue ETA retain their existing processing-progress meaning. A byte counter can include metadata or repeated physical reads and is therefore not substituted for logical file-completion percentage. Non-USB card-reader estimates retain their existing approximate display. This change does not claim to increase USB or SD throughput.

Validation: 216 extracted production transport/CRC/burst checks, 254 actual-built-app byte-rate/startup/stall/large-file checks, and 14 built-app ETA regressions passed. Tests include validated-only accounting, cache hits, speculative burst behavior, rejected CRC, counters beyond 4 GiB, and a simulated 100 GiB constant 43 MB/s transfer that remains displayed at 43 MB/s. The GUI compiled once as 150 with zero warnings/errors. Transport fixture-only unused-field warnings do not occur in the product build.

The prior 149 experiment measured a full 1.65057 GB V2 extent at 46.01 MB/s average (43.91–47.06 MB/s interval range), and export at 45.10 MB/s with an approximately 23 MB/s tail interval. It captured the old percentage-derived sawtooth. Those are 149 observations, not a hardware validation of 150. This fix used software checks only; V2 hardware ownership was returned to the firmware developer for separately authorized power work. No hardware calls, reset, flash, card writes or firmware changes accompanied this fix.

SDK, configuration/update helpers, firmware, buffering and recording/preview code retain the exact 149 bytes. The installer contains the same clean 34-file runtime payload with the new GUI. Release receipts include exact compiled-source hashes and the focused test results.
