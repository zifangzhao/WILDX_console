# Shared firmware window — WILD-X 1.0.0.148

V1 and V2 now use the same firmware window. Select a device by its V1/V2 label and exact MCU UID; the window selects its matching bundled firmware. Choose APP only or the full APP + USB + boot bundle, then Update bundled firmware. A V1 camera target remains an explicit selection for a physical camera board. Changing the device never starts an update and clears stale status/selection. A missing or ambiguous UID is not replaced with another logger.

The shared interface retains the distinct V1 and V2 USB update protocols. Full updates still validate the image, confirm the exact device, back up flash, preserve configuration/omitted bytes and verify readback. Unsupported commands are disabled. The V2 download/mode helpers and old-firmware fallback are retained. No firmware image bytes changed in this release.

The current V2 fused image intentionally ends at 0x081FD000, leaving 12 KiB of unused tail flash absent from the HEX. The earlier parser required a padded image through 0x08200000 and rejected it. The bundle parser now accepts omitted bytes only on the SHA-checked V2 route, still requires the recovery area and complete CRC-validated APP/USB payloads, and preserves absent bytes from the physical backup. V1's image-admission rules are unchanged. Missing recovery, APP-manifest or USB-vector records are rejected before writing.

Release cleanup: the installer contains only current runtime dependencies, current catalog images, the camera bundle and user documentation. Historical firmware, acceptance/source receipts, patches and debug output remain in repository history and release evidence, rather than being installed. LATEST_INSTALLERS has one current installer. The stale local bin/Release directory is archived outside the release output before installing the verified runtime payload there; no running installed app is stopped or updated by this packaging work.

Validation: 24 actual-window selection/layout checks and 130,128 actual-parser/guarded-DFU model checks passed. The models cover wrong UID, changed readback, configuration/upper-flash/omitted-tail preservation and refusal of missing required image bytes. Tests used fake programmers and did not discover, reset or flash connected hardware. GUI builds 146–148 incremented each time; only 148 is published. SDK, helpers, acquisition/recording/preview source bytes and bundled firmware are retained from 145.
