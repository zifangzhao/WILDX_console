# WILD-X 1.0.0.141

V2 SD-to-USB GUI export improved from **31.42 to 43.33 MB/s (+37.9%)** on the connected board/card/PC. These are medians of three buffered exports of the same preserved three-probe recording, compared with the already optimized 140/USB13ED release. All six alternating exports matched the reference DAT, descriptor and footer hashes, and all 296 catalog entries were preserved. The selected session contains no IMRO file, so this check does not establish IMRO generation.

The improvement combines a three-stage firmware pipeline with bounded USB commands and two host buffers. Firmware overlaps SD IDMA, CPU CRC and USB. The PC announces up to 32 full packets within the recording's range, then overlaps one synchronous native read with CRC validation of the previous immutable buffer. Every header, payload CRC, sequence, epoch and LBA remains checked before data is published. The worker is joined before cancellation or handle release; ambiguous commands are never replayed. Seeks and partial tails use the existing reader. Firmware without the explicit NBC1 capability also retains that reader.

Install this release and apply its bundled V2 USB firmware to obtain the measured combined improvement. The installer includes V2 APP8DE56637 / USBA71BDECC / recovery6408DBB8 and the matching catalog directly. V1 remains APP82E51DEA / USB4F7B521A. No separate update ZIP or new download setting is needed. The existing Run WILD-X installer finish option is retained.

The private host comparison measured 44.02 MB/s with CRC and test-only SHA256, versus 33.42 MB/s on the same A71 firmware through per-packet host commands (+31.7%). Physical-read and logical-export byte counts differ; use the GUI export comparison above for the user-facing gain. The unbuffered diagnostic export path remained around 31.17 MB/s versus 31.82 before. The GUI always uses the buffered wrapper for USB downloads. The initial firmware-only candidate gained about 6% and slowed catalog scans; it was held from release. The final firmware restores conservative metadata read-ahead and the host path delivers the useful gain. This illustrates why the complete pipeline must be measured.

Cancel/reopen at three timings preserved exact prefix hashes. A subsequent short P123 / 20 kHz USB capture verified all 7,280 blocks with zero reported raw or decoded drops; each probe produced 186,367 rows. All 186 native IMU observations had valid AG+MAG and unique sensor sequences. This capture used GUI140; its capture/IMU code and SDK are byte-identical in 141. The final six exports used the actual141 GUI. All observers closed and the exact device returned to idle USB mode2. No SD write, format or delete occurred.

Run `test_download_burst.ps1` for 183 software-only assertions covering legacy fallback, ranges/tails, buffer ownership, cancellation, integrity errors, unknown command outcomes and retirement receipts. The GUI was compiled once from the exact 140 graph plus three host files and its version. The SDK and other helpers were reused unchanged. The source archive records exact C# inputs and retained SDK sources; firmware provenance records the scoped incremental build and historical retained object identities, not a clean-tree whole-firmware reconstruction.

Performance is a bounded result on this card and PC, not an all-card or endurance guarantee. Only the USB firmware component was installed for these tests; the bundled fused image is assembled from the checked components. See checks/measurement-summary.json, checks/source-tests.json and the firmware acceptance/package receipts for exact identities and scope.
