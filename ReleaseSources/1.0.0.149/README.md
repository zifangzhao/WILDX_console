# V1 BLE LFP preview — WILD-X 1.0.0.149

V1 BLE waveform preview is now LFP only. It starts with one channel to reduce optional radio traffic during two-probe, 20 kHz SD recording. Firmware advertising compact preview still permits up to four selected LFP channels. USB preview and the stored AP/LFP streams retain their existing behavior.

The GUI previously defaulted to four AP traces and unchecked Preview on any startup/silence timeout. A validated first-session origin requires ten fragments, but its V1 firmware lease lasts only two seconds. The host's five-second wait did not renew that lease. Once a correlated partial origin supplies the device's real session, the host now renews the exact origin request tuple every 750 ms when controls/IMU permit. Failed or partially delivered snapshots are retired by their own ID and session, with lease expiry observed before retrying.

Preview remains checked on transport/data timeouts and resumes after bounded backoff. The validated origin is cached for the connection/probe/rate and sent with its real device session; firmware must admit that session before any new stream can produce data. Channel changes can reuse it. A failed cached attempt forces fresh validation. LFP phase is never guessed from packet ticks, because those ticks themselves depend on the phase requested by the host. Stopped/disconnected recordings clear the cache. Closing during recovery cancels safely.

Recording controls and IMU retain priority over all preview writes. The existing firmware's pressure policy can still suppress preview, and legacy V1 has no retransmission contract; genuine preview gaps remain visible. At 20 kHz the current V1 LFP decimation yields approximately 416.67 preview samples/s/channel. Stored samples and their timing are not resampled by this change. A missing/invalid firmware startup-origin cache cannot be repaired by a host retry; the GUI reports the wait instead of inventing a waveform.

Validation: 13,375 production-source checks passed with only the radio doubled. They include two-probe/20k LFP startup, partial-origin renewal, cached channel changes, partial-write cleanup, timeout/backoff/recovery, closure during recovery, compact and legacy decoding, recorded firmware AP/LFP vectors, CRC/framing, control priority and layout. The GUI compiled once as 149 with no warnings/errors. No connected hardware was accessed, reset, recorded or flashed. SDK, updater/configuration helpers, firmware images and acquisition code are the exact 148 versions. Source-only V1 developer coordination confirmed the lease/pressure behavior and prior APP82 mask3/20k LFP HIL evidence; that prior evidence is not a hardware test of 149.
